# POST_MVP_PLAN — aiGitWorktreeManager (gwm)

Границы MVP и идеи «на потом». Ничего отсюда не реализуется без явного запроса — это roadmap, а не бэклог обязательств. MVP (Этапы 0–6) закрывает: обзор worktree по всем репозиториям, orphaned-детекцию, create/remove, переключение. Этап 7 сделал обзор читаемым на терминале любой ширины. Этап 8 реализуется тремя последовательными PR; первый (конфиг-файл) — сделан.

## Явно ЗА границами MVP

- **Автоудаление orphaned worktree.** `gwm` в MVP только помечает и подсказывает; он никогда не удаляет worktree без явного действия пользователя. Автоочистка (даже опциональная) — сознательно отложена, чтобы не потерять незакоммиченную работу.
- **Не-git VCS** (Mercurial, jj/Jujutsu). Только git worktree.
- **Windows.** MVP таргетирует Linux/macOS (POSIX-шелл для cwd-обёртки). Windows-поддержка — отдельный вопрос (PowerShell-функция вместо bash-обёртки).

## Идеи на будущее

### UX / TUI
- **Full-screen TUI с авто-refresh.** Живая перерисовка (alternate screen) с автообновлением статусов по таймеру/файловому watch. Требует более тяжёлого TUI-режима Mordant — оправдано, только если line-oriented обзора станет мало.
- **Fuzzy-поиск по worktree** (в духе `fzf`) прямо в интерактивном списке при большом числе репозиториев.
- **Пометка «сколько коммитов ahead/behind upstream»** в таблице обзора. В работе как третий из трёх PR Этапа 8, вместе с возрастом worktree.
- **Возраст worktree** (последний коммит / последнее изменение файлов) для приоритизации уборки. В работе как третий из трёх PR Этапа 8.
- ~~Группировка вывода `scan` по репозиторию~~ **Сделано (Этап 8, второй PR).** Имя репо в колонке «Репозиторий» показывается только на первой строке каждой группы worktree одного репо, остальные — пустая ячейка (`ui/WorktreeTable.kt`, `OverviewRow.repoIsGroupStart`). Порядок строк не менялся — группировка чисто визуальная и опирается на то, что `ScanService` уже отдаёт worktree сгруппированными по репо (см. риск в `SKILL.md`: инвариант «соседние строки одного репо» не проверяется явно).
- **Сортировка вывода `scan`** — по статусу / orphaned / возрасту (по репозиторию уже не актуально — см. группировку выше). Осознанно НЕ сделано: обзор пока идёт в стабильном порядке обхода. Добавлять, когда портфель станет достаточно большим, чтобы ручной глаз не справлялся.
- **Ширина/набор колонок из конфига.** В Этапе 7 бюджетирование ширин — жёстко зашитая эвристика (`ui/TableLayout.kt`: `MIN_*`/`PREFERRED_PATH`, лестница деградации). Возможность задать предпочтения (какие колонки показывать, минимумы ширин) через конфиг-файл — отложена до реальной потребности.

### Скрипты и интеграция
- **`--format=json` / `--porcelain` для `scan`/`list`.** Машиночитаемый вывод для скриптов и интеграций (в духе самого git). Осознанно НЕ сделано в Этапе 7: единственный машинный контракт сейчас — `--print-path` (сырой абсолютный путь). Табличный вывод остаётся человекочитаемым; структурированный формат добавлять, когда появится конкретный потребитель (дашборд, CI-скрипт).

### Функциональность
- **Создание worktree из удалённой ветки** (`git worktree add --track -b ...`) одним действием, включая fetch.
- **Bulk-операции:** удалить все orphaned за раз (с обязательным подтверждением каждого dirty).
- **Интеграция с `aiProjectDashboard`** — экспорт обзора worktree как данных для дашборда проектов портфеля.
- **Хуки:** запускать команду после создания worktree (например, `direnv allow`, копирование `.env`).

### Производительность / упаковка
- **GraalVM native-image** — мгновенный старт без JVM, один бинарь. Оправдано, только если холодный старт JVM (~0.3–0.5 с) начнёт реально мешать в повседневном использовании.
- **AppCDS** — более лёгкий способ ускорить старт JVM без перехода на native.
- **Distribution:** публикация как SDKMAN-кандидат / Homebrew formula, если инструментом захотят пользоваться другие.

## Границы, которые НЕ двигаем

- Никакой сети, никакого сервера, никакой телеметрии. Инструмент остаётся полностью локальным и офлайн.
- `gwm` не пишет в `.git` напрямую — всегда через настоящий `git`.
- Не редактирует dotfiles пользователя сам — только предлагает готовый сниппет shell-функции.
